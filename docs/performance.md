## 条件と測り方

2026-09-16、Headless CLI / .NET 10。Release・Debug、記録なし・ありを別プロセスで順次実行し、ビルド・テストとは重ねていない。各実行は `--ticks 20000 --warmup 200`、入力なしのお任せ。warmupは独立したSimulationで行い、本計測はS0から再開する。終了した場合は終了tickまで。統計はS1以降で、S0・warmupは除く。

20人=`TestData/week3-20.json`、40人=`TestData/week2-2routes.json`、80体=`TestData/week3-80.json`。すべて2経路、seed=0、陣営上限40、検証上限36000tick。兵数は初期人数であり、増援・死亡を通常どおり処理する。人数固定の負荷試験ではない。試合時間・兵数推移・命令履歴・墓石数も異なるので、人数と所要時間は単純な比例関係にはならない。

`Compute` はStepと正規状態・StateHash/EventHash計算の時間。`ReplayIO` はreplayレコード組立・書き出し区間。`TickWithIO` はその両方を含む。通常のバッファ付きファイル出力であり、tickごとのfsyncはしない。`WallTotalMs` は初期化、S0、ヘッダー、End、最終flush/closeも含むが、warmupと結果JSON保存は除く。ファイルI/Oで誘発されたGC等が別の段階に現れる可能性があるので、記録ありComputeと記録なしComputeは別の実測値として扱う。

p50/p95/p99は昇順に並べたtick時間の `ceil(p*N)` 番目（nearest-rank）。段階は同じtickの複数呼出しを合計し、未実行tickは0。入れ子の経路探索時間は呼出元から差し引く。段階のp95同士を加算して全体のp95とはしない。全体にはループ、入力検証、計測通知等の残余時間も含む。外部入力のcodec往復検証は両モード共通で計算側に含む。入力がある場合、記録なしでも入力レコード書き出し境界の計測通知費用がReplayIOに入るが、ファイルへの書き出しは行わない。本表はすべて入力なし。

| 区分 | 計測範囲 |
|---|---|
| Pathfinding | GridMap.FindPath（A*）とSharedRoute（逆向きBFS・キャッシュ照会・経路列生成）。呼出元から除外 |
| AI | DecideArmies：観測準備、方針判断、軍団配分。経路探索を除外 |
| EnemySearchCombat | GenerateIntentsの敵検索・戦術意図生成、Attack、ResolveDeaths |
| Visibility | 移動後と増援後のUpdateVisibility、UpdateObservations（軍団接触更新を含む） |
| Commands | 入力適用、待ち命令適用、方針合成、命令終了判定 |
| Canonical | CaptureDiagnosticによる正規状態書き出しとStateHash/EventHash計算 |
| Movement | 移動・隊列・経路追従。経路探索を除外 |
| ObjectivesReinforcements | 拠点占領、増援、勝敗判定 |
| Frames | PublishFrames：陣営向けフレーム構築、FogViewコピー等 |
| ReplayIO | tick内のreplayレコード組立・書き出し区間。実際の記録は記録モードのみ |

Headlessなので描画時間は対象外。壁時計はCLIのStopwatchだけで読み、Simulation/Application/GridMapは段階名と開始・終了だけを通知する。時間値を判定へ返さず、正規状態・Contracts・再生形式には追加しない。

## 判定と解釈

指定されたRelease・80体・記録なしのp95は **21.525 ms < 25 ms** で仮目標を達成した。改善前の時点で達成しているため、性能最適化は0件。改善後として表示する別測定値はない。計測通知以外のゲーム処理・更新順は変更していない。

目標判定の対象は依頼の実測条件であるRelease・記録なしと解釈した。Debugの80体p95は記録なし35.362 ms・あり38.168 msで25 msを超える。Debugまで達成したとは扱わない。

80体の平均時間はAI判断・配分5.372 ms、経路探索3.046 ms、正規状態・ハッシュ1.145 msの順に大きい。AI区分には判断用観測作成と軍団配分を含むため、この集計だけで特定の関数を原因と断定しない。将来の未達時はまずAI区分を細分化し、その後経路探索と正規状態書き出しを調査する。

40人の平均・p95が80体より大きいのは、測定区間・試合展開が異なる比較であることに注意する。40人ではAI平均6.004 ms・経路探索平均4.118 msが80体より大きいことは確認できるが、人数を増やすほど速くなるという結論にはしない。

各条件1回の測定であり、PC間・Unity描画を含む性能の保証ではない。PC仕様は上の追記欄に後日記載する。
