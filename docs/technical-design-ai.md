# 技術設計：ゲーム内AI（参謀と細かい判断、案、2026-10-04）

企画書4章「AIの役割」、8章「指示の出し方とUI」、9章「生成AIの接続」、12章「AIとLockstepの関係」を、今のコードの上でどう作るかを決める資料です。数字は【】で示した仮の値で、測定で調整します。

## 0. オーナーの決定（2026-10-04）

- **3つの AI を役割で分けて使う**
  - 参謀：Claude API と ChatGPT（OpenAI）API。差し替えできるようにする
  - 細かい判断：Jev（TypeSafe AI の System One モデル。ロリポップ！AIゲートウェイ経由）
- **参謀（LLM）への問い合わせは、できるだけ少なくする。細かい判断は Jev に任せる**
- **費用の目安は、普通に遊ぶなら1試合【3円】（月1,000円）、たくさん使う人で1試合【10円】（月3,000円）**。上限ではなく目安（4章）
- **使う AI は人が状況に応じて選び、かかる費用を表示する**（オーナー追加の決定、同日）
  - 話しかけるたびに、参謀のモデルを選べる：Claude（Haiku・Sonnet）、ChatGPT（Luna・Sol）、**Jev**、**ローカル LLM**
  - 細かい判断も、Jev とローカル LLM を切り替えられる
  - 送る前の見積もり、返ってきた後の実際の額、1試合の合計を表示する
  - お金を使いたくない人は、ローカル LLM だけで遊べる（費用0円）
- **AI で指揮することがこのゲームの本体**（同日、オーナー）。AI なし（ルールのお任せ AI とボタンだけ）を入り口として勧めない。それでは AoE との違いがなくなる
  - 最低限の AI は、プレイヤーに導入させずゲーム側で用意する。**A と B の両方を採る**（同日、オーナー）：
    - (A) 小さいローカル LLM をゲームに同梱して中で動かす（どのモデルにするかは G-2 の測定で決める）
    - (B) **運営が1ユーザーあたり【100円】分を無料で負担する**。Jev だけでなく Claude・ChatGPT も含めた合計。キーなしで全部の AI を試せる（通常設定の1試合3円なら約33試合、Jev だけなら約200試合）。使い切ったら、自分の API キーかローカル LLM に移る
    - (B) には、運営の中継サーバー（キーを配布物に入れないため）、ユーザーの識別、使った額の記録、複数アカウントで無料分を取り直す不正への対策が要る。作るのは Ver.4（オンライン対戦）の前後。それまでの開発中は、オーナーのキーを手元で使う
  - 段階：最低限の AI（同梱のローカル LLM／運営負担の Jev）→ 自分で入れる大きいローカル LLM → Claude・ChatGPT（自分の API キー）。上の段ほど参謀が賢くなることを、画面で分かるようにする（AI がどう判断してどう動いたかを見せる）
  - ルールのお任せ AI は、AI の返事が遅れた・失敗したときに軍を止めないための土台として、裏で必ず残す（企画書4章）
- **試合の長さと速さ**（同日、オーナー）：人が全部を操作できない量が前提なので、ゲームを速くしても、AI に任せれば同じ体験ができる。平均15分のまま、内政（集める速さ・建てる／訓練する時間・時代を進める時間）を中心に縮める。兵の移動と戦闘は速くしすぎない（大軍の戦いが読めなくなるため）。人と LLM の判断の時間はゲームの速さで縮まらないので、条件付きの作戦（2.2）と速い層（Jev・ルール）で吸収する。調整はゲーム内 AI が入ってから
- Claude は **API キー**でつなぐ。Claude のサブスク（Pro/Max）や Claude Code をゲームから呼ぶことは、Anthropic が事前の承認なしには認めていない（Agent SDK の概要ページに明記）。承認が取れたら、差し替え口に足す
- 実装は Codex に段階ごとに発注し、レビューはオーナー側の Claude がする

## 1. 3つの層

| 層 | 担当 | 呼ぶとき | 仕事 | 失敗・遅れたとき |
|---|---|---|---|---|
| 参謀（賢い・遅い・高い） | 人が選ぶ：Claude API / OpenAI API / Jev / ローカル LLM | 人が話しかけたとき、大きな局面の変わり目（2.3） | 言葉を方針の命令に直す。条件付きの作戦を組む | 命令なし。理由を短く報告する |
| 細かい判断（速い・安い） | 人が選ぶ：Jev / ローカル LLM | 【10秒】ごと（初期設定。4章）、または出来事のとき | 作戦の条件を満たしたか、どの拠点が危ないか、引くか粘るか、などを選択肢から選ぶ | 確信度が【0.6】未満、または失敗なら、何も変えない |
| 実行（決定論） | 今のお任せAI・戦術AI | 毎tick | 移動・戦闘・内政 | AI の返事がなくても、今の方針のまま続く |

- 3つとも、**同期する前（各プレイヤーの PC）で完結する**。出力は、今と同じ「方針の命令」（`PolicyOrder`・`EconomyCommand`・区域の担当）になり、リプレイに記録される。シミュレーションは AI を呼ばない（企画書12章）
- AI に渡すのは、その陣営が観測できた情報（`FactionObservation`・自陣の `EconomyView`・区域の一覧）だけ（技術ルール6）

## 2. 参謀（LLM）

### 2.1 言葉 → 命令（最初に作る）

- 入力：人の指示文（チャット。音声は後で同じ口に入れる）、話し始めた時点で選んでいた対象（拠点・部隊・区域）、戦況の要約
- 出力：**決まった語彙の命令の並び**（JSON。LLM のツール呼び出し／構造化出力で形を強制する）と、人に見せる一言（「北軍：拠点防衛を継続」など）
  - 方針：`Focus`・`Defend`・`AllowAbandon`・`Retreat`・`MaintainReserve`・`Scout`・`ReturnToAuto`。範囲は全部隊・部隊・拠点・区域
  - 区域の担当：`SetRegionControl`
  - 内政：方針（`SetEconomyPolicy`・区域の方針）、時代を進める、建物を置く、訓練
  - 「わからない」：対象が不明・対応していない指示。理由を一言付ける。**曖昧なまま実行しない**（企画書8章）
- 変換の結果は、ゲーム側で検証してから命令にする（存在しない拠点、自分の物でない部隊などは捨てて報告）
- 人の言葉を直したものは**人の命令**（`CommandSource.Human`）として出す。解釈している間は、今の `CommandGateway.SubmitInterpreted` の予約（対象を固定し、その対象への古い AI の返事を止める）を使う。締め切りは【12秒】（今の `AiTimingProfile.Default`）
- 「直前の命令を取り消す」は LLM を通さずに出す（今の `Cancel`）

### 2.1.1 モデルの選び方と費用の表示
- 指示を送るたびに、使う参謀を選べる（前回の選択を覚えておく）。選択肢：

| 選択肢 | 向いている指示 | 1回の費用（目安） |
|---|---|---|
| Claude Haiku 4.5 | 普段の指示 | 約0.2〜0.45円 |
| Claude Sonnet 5.5 | 複雑な指示・作戦の組み立て | 約0.9円 |
| gpt-6-luna | 普段の指示 | 約0.05円 |
| gpt-6.1-sol | 複雑な指示・作戦の組み立て | 約0.9円 |
| Claude Opus 5.5（$4/$20） | 序盤の作戦をじっくり組む | 約1.8円 |
| Claude Fable 5.1（$10/$50） | 一番大事な判断 | 約4.5円 |
| gpt-6-astra（$10/$50） | 一番大事な判断 | 約4.5円 |
| Jev | 決まった形の短い指示だけ（下の注意） | 約0.005円 |
| ローカル LLM | お金を使いたくないとき | 0円（速さ・正確さは PC 次第） |

- **上位のモデル（Opus・Fable・Astra）の注意**：考えてから答えるので遅く、今の締め切り【12秒】を超えることがある。考える分も出力として課金されるので、実際の額は目安より高くなりやすい。急ぎの指示（コアの防衛など）には向かない。締め切りはモデルごとに設定で持つ（上位のモデルは【60秒】など）。締め切りを過ぎた答えは、今の決まりどおり捨てる
- **Jev を選んだときの注意**：Jev は文章を組み立てず、選択肢から選ぶモデル。そのため「指示の種類」「対象」「目標」を、戦況の名前の表から選ばせる形で直す。決まった形の指示（「北を守れ」「第2軍は引け」「区域3は任せる」）だけを受け付け、複雑な指示（条件付きの作戦、複数の命令）は「Jev では直せません。別の AI を選んでください」と理由を返す
- **ローカル LLM**：PC の上で動く LLM（Ollama・LM Studio など）に、それぞれのソフトが用意している HTTP の窓口でつなぐ。接続先とモデル名は設定で決める。試合の前に動くかを確かめ、動かなければ選択肢に出さない
- **費用の表示**：
  - 送る前：選んだモデルと、戦況の要約の長さから見積もった額（「約0.3円」）
  - 返ってきた後：答えに付いてくるトークン数から計算した、実際の額
  - 1試合の合計と、予算（4章）の残り
  - 価格表は設定ファイルに持つ（各社の値上げ・値下げに追いつけるように）。1ドルの円の値も設定で変えられる

### 2.2 条件付きの作戦（1回の判断を長く活かす）

- 参謀は、その場の1手ではなく、**数分続く作戦**を返せる：条件と行動の組み合わせを、決まった語彙で並べる
  - 条件の例：拠点 X の所有者が変わった、拠点 X の近くに敵が N 以上いる、自軍の兵が N 以下になった、時間が T を過ぎた、**Jev の判断「X が危ない」が真**
  - 行動の例：2.1 の命令のどれか
- 作戦はゲーム側の「作戦の表」に置き、条件の判定は毎回 LLM を呼ばずに行う（ルールで判定できる条件はルールで、判断が要る条件は Jev で）
- 自由な文章やプログラムを、同期した後の処理に解釈させない（企画書4章）。作戦の表は各 PC の外側（Application 層）にあり、発火したときに出る命令だけが同期される

### 2.3 参謀を呼ぶ契機（問い合わせを減らす）

- 人が話しかけたとき（毎回）
- 大きな局面の変わり目だけ（自律）：コアが攻撃された、拠点を失った・取った、時代が進んだ、敵の新しい兵種や文明を見つけた、作戦が終わった・失敗した
- 定期の呼び出しはしない（今の `AutonomousPollSchedule` の20tickごとの判断は Jev 用に使う）
- 同じ対象への問い合わせは、終わるまで1件まで（今の自律の要求と同じ決まり）

### 2.4 費用を抑える工夫

- 普段の参謀は軽いモデル（Claude Haiku 4.5 か gpt-6-luna）。中くらいのモデル（Claude Sonnet 5.5・gpt-6.1-sol）は、大きな判断のときだけ（オーナー設定）
- 変わらない前置き（語彙の説明・ルール・例）を先頭にまとめ、プロンプトの使い回し（Claude のプロンプトキャッシュなど）を効かせる。戦況は後ろに短く付ける
- 戦況は要約して渡す（兵の一覧ではなく、拠点・部隊ごとの数と状態）。1回の入力は【2,000トークン】以内を目安にする

## 3. 細かい判断（Jev またはローカル LLM）

- Jev とローカル LLM を、設定で切り替えられる。どちらでも同じ設問を使う（ローカル LLM には、設問を「選択肢から1つ選び、確信度を0〜1で付けて、決まった JSON で答える」形の指示にして渡す）
- 費用は2.1.1と同じく表示する（Jev は1回約0.005円、5秒ごとで15分なら約1円。ローカル LLM は0円）。ローカル LLM が5秒に間に合わない PC では、間隔を延ばす
- 今の `JevPolicyProvider`（`Providers/`）の形を広げる：観測を `JevState` の文にし、設問（choice／noul／score）を送り、確信度つきの答えを受け取る
- 設問の例：
  - どの拠点が一番危ないか（choice）
  - 部隊 X は引くべきか（noul）
  - 作戦の条件「北が崩れた」を満たしたか（noul）
  - 指示文の振り分け（攻める／守る／引く／内政／わからない。LLM の前段に置き、定型の指示は LLM を呼ばずに済ませる）
- 確信度が【0.6】未満、失敗、時間切れのときは、何も変えない
- Jev の答えから命令を出すときは、AI の命令（`CommandSource.Ai`）として、観測した tick と失効条件を付ける（今の自律の要求と同じ）。**人の命令が優先**
- 設問の書き方は、Ver.2 で分かった決まりに従う（`memory/jev-question-design-rules.md`：「〜である」と書く。設問が頼る区別は、state に語として載せる）。設問の文言を変えたら版を上げる

## 4. 予算（目安。上限ではない）

オーナーの考え（2026-10-04）：1試合15分、1日10試合を毎日遊ぶとして、
- **普通に遊ぶなら月1,000円くらい＝1試合【3円】**（初期設定はこれを目指す）
- 面白さが分かってきた人なら月3,000円くらい＝1試合【10円】
- どちらも目安で、超えても止めない（超えそうなときに知らせるだけ）。お金を使いたくない人はローカル LLM で0円

| 設定 | 1試合の目安 | 細かい判断 | 参謀の初期のモデル | 参謀を呼べる回数の目安 |
|---|---|---|---|---|
| 節約 | 0円 | ローカル LLM | ローカル LLM | PC 次第 |
| **通常（初期設定）** | **約3円** | Jev を【10秒】ごと（90回で約0.5円） | gpt-6-luna（約0.05円） | 40回以上（Claude Haiku を選ぶと約10回） |
| たくさん使う | 約10円 | Jev を【5秒】ごと（180回で約1円） | Claude Haiku 4.5（約0.2円） | 約40回 |

- 上位のモデル（Opus・Fable・Astra、1回約1.8〜4.5円）は、人が選んだときだけ使う。自律の呼び出し（2.3）には使わない
- 1回の値段の目安：Jev 約0.005円（入力800トークン、$0.042/100万。出力は無料）、Claude Haiku 4.5 約0.2円（キャッシュが効いた場合。効かないと約0.45円）、gpt-6-luna 約0.05円
- 1ドル＝150円、1回は入力2,000・出力200トークンとして計算した（価格は 2026-10-04 に各社の価格表で確認）
- **予算のメーター**：1試合の使った額を、返ってきたトークン数から数えて表示する。モデルは人が選ぶ（2.1.1）が、予算を超えそうなときは知らせる。設定で「自動で安くする」をオンにしたときだけ、残りが【3割】を切ったら軽いモデル、【1割】を切ったら Jev かローカル LLM、なくなったらルールだけに切り替える（企画書9章「利用上限への対応」）。自律の呼び出し（2.3）は、この切り替えに常に従う
- 予算・モデルの選び方は、オーナーが設定で変えられる（「通常／節約／高性能優先」）

## 5. 差し替え口と安全

- 新しい差し替え口（Application か Providers）：
  - `ICommandInterpreter`：言葉 → 命令（Claude／OpenAI／Jev／ローカル LLM／偽物）。要求ごとに使うモデルを指定できる。答えには、使ったトークン数と費用（円）を付ける
  - `IJudgement`：設問 → 答え（Jev／ローカル LLM／偽物）。答えに費用を付ける
  - 費用の計算と価格表、予算のメーターは、差し替え口とは別の部品にする（どのモデルでも同じ数え方）
  - どれも非同期で、今の `IPolicyProvider` と同じく「積んで、すぐ返す・できたものを順に受け取る」形にする。シミュレーションの tick を待たせない
- API キーは環境変数から読み、HTTP のヘッダーにだけ置く。ログ・状態・例外の文に出さない（今の `HttpJevTransport` と同じ）
- AI には「戦況を受け取る」「決まった語彙の命令を返す」以外の権限を与えない（企画書9章「安全性」）
- 外部へ戦況を送ることは、プレイヤーに表示して同意をもらう（製品の判断。最初の試作では設定画面の注意書き）
- 共有する命令ログには、指示文・AI の説明文を入れない。本人用の記録は別に保存する（企画書12章）

## 6. 段階（それぞれ Codex に発注）

| 段階 | 作るもの | 完了の目安 |
|---|---|---|
| G-1 | 命令の語彙（JSON の形）、検証、命令への変換、「わからない」の理由。モデルを選べる差し替え口と、費用の計算・価格表・予算のメーター。偽物の参謀で動かす。CLI `say`（ヘッドレスの試合に指示文を流す） | 偽物の答えから正しい命令が出る。不正な答えは捨てて報告。費用が計算される。決定論とリプレイが壊れない |
| G-2 | Claude API と OpenAI API とローカル LLM の接続（API キー・締め切り・トークン数）。指示文の評価セット（日本語の指示【50】個と正解の命令） | 選べる全モデルで、正解率と応答時間（p50・p95）と1回の費用を測り、表にする |
| G-3 | Jev の設問を広げる（危ない拠点、引くか、条件の判定、決まった形の指示の変換）。細かい判断をローカル LLM でも動かす | 正解のある戦況で、Jev とローカル LLM の正解率と速さを測る。確信度が低いときに何もしない |
| G-4 | 条件付きの作戦の表（参謀が作り、ルールと Jev が判定し、発火したら命令を出す） | 作戦が数分続き、その間参謀を呼ばずに済む |
| G-5 | 試し遊びへの組み込み（チャット欄は相方。A 側は差し替え口と `LiveMatchHost` への結線）。報告（事実／不明／代償） | 遊びながら話しかけて、命令が出る。予算のメーターが見える |
| 後で | 音声（Whisper など）、教範、試合間のメモリ、ローカル LLM | |

## 7. 確かめること（未決）

- 参謀を Claude と OpenAI のどちらにするか：G-2 の評価セットの正解率・速さ・費用で決める
- 最低限の AI を、同梱の小さいローカル LLM にするか、運営負担の Jev にするか：G-2 で小さいローカルモデル（決まった JSON の形に縛って答えさせる）の正解率・速さ・必要な PC の性能を測って決める
- 誰が費用を払うか（プレイヤーの API キーか、運営が中継して月額などに含めるか）：Ver.4（オンライン対戦）までに決める
- Jev のゲートウェイ経由の速さ（Ver.2 の実測は p50 約1秒・p95 約4秒。記事の 70〜500ms との差）
- 初期設定で1試合3円に、局面の変わり目の呼び出しが本当に収まるか：G-4 の後に試合で数える
