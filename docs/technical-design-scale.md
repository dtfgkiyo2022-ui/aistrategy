# 技術設計：規模と操作量（案、2026-10-03）

企画書の「AIによって人間の操作限界を取り払う」を、ゲームの規模として作るための設計です。オーナー決定（2026-10-03）の順番は次のとおりです。

1. 操作量の物差しを決める
2. 試合の規模を上げる
3. 方針の出し方（分担）を整える

ゲームの中に会話する AI を入れるのは、この後です。3は、会話する AI の受け口にもなります。

この文書は `docs/technical-design.md`（Ver.1）と `docs/technical-design-v3.md` の契約に足すものです。矛盾したら、そちらを優先します。

---

## 0. 今の規模（2026-10-03）

| 項目 | 今の値 |
|---|---|
| マップ | 256m×128m（2m のマス、128×64） |
| コア | 1陣営1つ |
| 前線の拠点 | 2つ |
| 人口の上限 | 60（村人と兵の合計。`EconomyRules.PopulationCap`） |
| 開始時の兵 | 40体（両陣営の合計） |
| ベルト | 1陣営200マスまで |
| 処理の重さ | 480体で 1tick 約10〜12ms（予算は 50ms＝20Hz）。重いのは正規状態の書き出しとハッシュ |

この規模なら、人の手でほぼ回せます。

## 1. 操作量の物差し（S-1）

### 1.1 何を数えるか
「プレイヤーが手を入れたくなる場面」を、試合の中の出来事として数えます。お任せ同士の試合を Headless で流し、1分（1200tick）ごとの数を出します。

| 種類 | 出来事の例 |
|---|---|
| 内政：人 | 村人が手持ち無沙汰になった、資源点が尽きて村人が移った |
| 内政：建物 | 建物が完成した、訓練・研究が終わった（次を選ぶ場面）、人口の上限に達した |
| 内政：ライン | ラインが詰まった・切られた、加工の建物が材料待ちで止まった |
| 戦闘 | 敵を新しく見つけた、部隊の HP が半分を切った、拠点の持ち主が変わった、コアが攻撃された |
| 時代・文明 | 時代を進められるようになった |

あわせて、同時に動いているものの数（建物、ライン、部隊、戦線＝敵と接している拠点・道の数）も数えます。

### 1.2 目安
- 人がこなせる意味のある判断は、1分あたり **20〜40** ほどと見ています（上手な人の操作回数は1分に100〜200ですが、意味のある判断はその一部です）。
- 目標の曲線：
  - 序盤（0〜5分）：1分あたり **20前後**。人が全部こなせる
  - 中盤（10分ごろ）：**60以上**。半分くらいは AI に任せないと回らない
  - 終盤（15分以降）：**120以上**。分担なしでは回らない
- 今の規模の値を最初に測り、目標との差を2の規模の設計に使います。

### 1.3 作り方
- シミュレーションの中には何も足しません。数えるのは観測用の道具（`Simulation.PhaseHashObserver` と同じく、通常の試合では何も計算しない形）、または Headless の CLI のサブコマンド（`load`）にします。
- 状態ハッシュ・正規状態・挙動を変えないことを、テストで示します。
- 出力は分ごとの表（CSV）です。種をいくつか流して、平均とばらつきを出します。

## 2. 試合の規模を上げる（S-2〜S-4）

新しい規模は、**新しい地図の版（`mapgen-4`）と旗で切り替えます**。今の地図（mapgen-1〜3）のバイト列・挙動・テストは変えません。

### 2.1 目標の値（案）

| 項目 | 今 | 目標（案） |
|---|---|---|
| マップ | 256×128m | **512×256m**（マスは2mのまま、256×128） |
| 前線の拠点 | 2 | **6〜8**（真ん中の帯と左右の縁に散らす） |
| 資源地 | コアのまわり＋散らばり | 地図のあちこちに**資源の固まり**を置く（遠征して取りに行く価値を作る） |
| 人口の上限 | 60 | **200**（住居で上げる。兵は最大で150前後） |
| 自分の町 | コア1つ | コア＋**支城（新しい建物）を2〜3**。支城は資源の受け取り・村人の訓練・近くの建物の建設の拠点になる |
| ライン | 数本 | 加工の連鎖を複数の町で組むので、**数十本** |

数字は案です。S-1の物差しで、1.2の曲線に近づくように決め直します。

### 2.2 段階（それぞれ Codex に発注）
- **S-2 地図の拡大**：`mapgen-4`（512×256、拠点6〜8、資源の固まり）。決定論と公平さの規則（コアの近くに最低限の資源）は今と同じです。重さは 2 倍のマス数で測ります（経路探索・視界の計算が増える）。
- **S-3 支城**：新しい建物 `Outpost Town`（仮の名前）。村人の訓練・資源の受け取り・時代に関係しない内政の拠点にします。お任せは、資源の固まりのそばに支城を建てます。Contracts に建物の値を1つ足します（告知は Issue #135）。
- **S-4 人口と兵の数**：人口の上限を200に上げ、兵の訓練・お任せの軍の編成が150体前後で回るか確かめます。重さを測ります（目安は 1tick 50ms 以内。正規状態の書き出しが重ければ、記録の間隔の見直しを別に考える）。

### 2.3 重さと決定論
- 数百体・数十本のライン・広い地図で、経路探索（`GridMap.FindPath`）、視界、正規状態の書き出しが重くなる見込みです。各段階で `bench`（`AllocKBPerTick`・処理ごとの ms）を測り、PR に書きます。
- `float`・`double`・`Dictionary` の列挙順を判定に使わないなど、決定論の決まりは今までどおりです。

## 3. 方針の出し方を整える（S-5）

人が「北は任せる、南は自分で」「町Aの内政は任せる、町Bは自分で」と分担できるようにします。会話する AI も、この同じ形で命令を出します。

- **担当の範囲**：「区域」（拠点・道・町）ごとに、担当を「AI」か「自分」に切り替えます。今の「人の操作が最優先」「AIに戻す」を、区域ごとに持たせる形です。
- **区域ごとの方針**：攻める・守る・内政を伸ばす・資源を取るなど。今の方針（`PolicyKind`、内政の方針）を区域に結びつけます。
- 命令は今までどおり `ICommandPort` 経由です。Contracts には、区域の ID と担当の切り替えの命令を足します（告知は Issue #135）。
- 表示（区域の担当の見え方、切り替えのボタン）は相方の担当なので、Issue で依頼します。

## 4. 進め方
- 実装は Codex に発注し、オーナー側の Claude が設計・レビュー・検証・マージを行います。
- 各段階は旗で切り替え、旗がオフなら今までと同じです。
- S-1 の物差しの最初の測定結果を見てから、2.1 の数字を決め直します（オーナーに報告します）。
